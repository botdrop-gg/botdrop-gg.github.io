Run your bot 24/7

Your bot only works while a computer is running it. If you run it on your own PC, it stops when the PC is off or asleep. This guide shows the easiest way to keep it online all the time, with no coding and no typing commands. Everything happens in your web browser.

Prices and limits checked October 2026. Hosting companies change their prices, so check their page before you sign up.

Our recommended path: GitHub + Render

  • Cost: about $7.25 a month, paid to Render, not to us ($7 for the smallest always-on server plus about $0.25 for 1 GB of storage that remembers what the bot already posted). Render needs a credit or debit card.
  • Time: 20–30 minutes to put it online 24/7 the first time. (Just running it on your own PC takes about 5 minutes.)
  • Why Render: our bots already include a setup file for it (render.yaml), so Render fills in most of the settings for you.
  • Why not free? Render's free plan is only for websites and goes to sleep after 15 minutes without visitors, which would knock a Discord bot offline. Always-on bots need the paid plan.

✅ Tested Oct 16, 2026: we followed these exact steps with a new GitHub and Render account and the Gaming Community Kit. The bot went live and answered /rules in Discord. Websites change their buttons from time to time, so if something looks different, email hello@getbotdrop.com.

One-click PC setup (Windows)

Don't need it online 24/7? Run it on your own Windows PC with our one-click launcher: no Python, no typing commands. Download BotDrop-<Product>-windows.exe from your Gumroad library (it's a separate download, next to the zip).

  1. Make a folder for it, for example Documents\BotDrop, and move the .exe there. The launcher saves its settings next to itself, so keep it in that folder.
  2. Double-click the file. Windows may show a blue box saying "Windows protected your PC". Click More info, then Run anyway. This shows up because the launcher is new and not yet code-signed. Some antivirus apps may also warn about it for the same reason.
  3. Follow the setup window. It walks you through every click, with pictures. Command bots (Gaming Community Kit, Mod Bot): create the bot, turn on the two switches, copy the token, then invite the bot with the Open invite link button. You can't continue until the bot has joined your server. Alert bots: create a webhook in Server Settings → Integrations → Webhooks → New Webhook → Copy Webhook URL, paste it, and click Send test message.
  4. Click Start. A small status window shows Online in: <your server> (or a warning if the bot isn't in a server yet). You can close it: the bot keeps running from the BotDrop icon in the system tray (bottom right, near the clock; click the ^ arrow if you don't see it).
  5. Tray icon menu: Status opens the status window, Open log shows what the bot is doing, Start with Windows (tick it to start the bot automatically when you log in to Windows), and Stop bot.

Good to know: the bot runs only while your PC is on and awake. If the PC sleeps or shuts down, the bot goes offline until you start it again. For 24/7, use the Render steps below. Your token or webhook is saved only on your PC, in a file called .env next to the launcher. Delete .env to run the setup again. To change games or channels, open config.yaml in the launcher's folder with Notepad (alert bots also have a Settings button in the status window), save it, then stop and restart the launcher.

✅ Tested: the Gaming Community Kit launcher was tested from a fresh folder on a real Windows PC (Oct 16, 2026): setup, invite step, status window, tray icon and /rules all worked. The launchers for the other bots use the same code and are beta until we've tested each one on a real Windows PC. A Linux version (beta) is also available. There's no Mac version yet.

Before you start

Unzip the file you downloaded from Gumroad. Inside is one folder (for example 09-discord-gaming-community-kit). Open its README.md to see which settings your bot needs. There are two kinds:

  • Bots that reply to commands (Gaming Community Kit, Mod Bot) need a bot token. A token is like a password that lets your bot log in to Discord. Never share it.
  • Alert bots (Deal Alert, Free Games Radar, Patch Tracker, Player Count, Stream Alert and others) only need a webhook URL. That's a private web address that lets the bot post into one channel.

How to get a Discord bot token (command bots)

  1. Go to discord.com/developers/applications and log in with your Discord account.
  2. Click New Application, type your bot's name, tick the box to agree, and click Create.
  3. Click Bot in the left menu. Here you can set your bot's picture and name.
  4. Scroll to Privileged Gateway Intents, switch on Server Members Intent and Message Content Intent, and click Save Changes. Our command bots need both.
  5. Scroll back up and click Reset Token, then Copy. Paste it somewhere safe for now. Discord only shows it once. If you lose it, just reset it again.
  6. To add the bot to your server, click Installation in the left menu. Under Installation Contexts, tick Guild Install. Under Default Install Settings → Guild Install, add the scopes bot and applications.commands and the permissions listed in your bot's README, then click Save Changes. Under Install Link, choose Discord Provided Link, click Copy, open the link in your browser, pick your server, then Continue → Authorize. (The Windows launcher below builds this invite link for you.)
  7. You'll also need your server ID (GUILD_ID). In Discord, open User Settings → Advanced and switch on Developer Mode. Then right-click your server's icon and click Copy Server ID.

How to get a webhook URL (alert bots)

  1. In Discord, hover over the channel where alerts should appear and click the ⚙️ (Edit Channel).
  2. Click Integrations, then Webhooks, then New Webhook.
  3. Give it a name and picture if you like, then click Copy Webhook URL.

Put your bot online, step by step

  1. Make a free GitHub account at github.com/signup. GitHub is where your bot's files will live, so Render can find them.
  2. Create a private repository (a "repository" is just a folder on GitHub). Go to github.com/new (or click the + at the top right, then Create new... → New repository). Name it, for example my-discord-bot. The visibility choice starts on Public, so change it to Private. Then click Create repository.
    Keep it Private. Your license doesn't allow sharing the template publicly.
  3. Upload your bot's files. On the new repository page, click uploading an existing file (or Add file → Upload files). Open the unzipped folder on your computer, select everything inside it (not the folder itself), and drag it onto the page. Then click Commit changes.
    Check it worked: you should see render.yaml and Dockerfile in the main list, not inside another folder.
  4. (Optional) Change the bot's settings. Click config.yaml, then the ✏️ pencil icon, and edit things like which games or channels to watch. Your README explains each line. Click Commit changes when you're done.
  5. Make a Render account at render.com. Signing up with GitHub is easiest.
  6. Create the bot on Render. In the Render dashboard, click + New, then Blueprint.
    1. Render first shows an Add Card window. Enter your card. Render places a temporary $1 hold to check the card. It is not charged.
    2. Render asks to install its app on GitHub. Choose Only select repositories, pick your bot's repository, and confirm. GitHub may ask you to Confirm access. If it does, choose Verify via email and type in the code GitHub emails you.
    3. Back on Render, your repository appears in the list. Click Connect next to it.
  7. Paste your secrets. You'll see a form with a Blueprint Name (any name is fine) and Branch (leave it on main). Render reads render.yaml and asks you for the settings it needs, like DISCORD_TOKEN and GUILD_ID, or DISCORD_WEBHOOK_URL. These are called environment variables, which just means settings stored on Render instead of inside your files. Paste each value. Leave optional ones (like AI keys) blank if you don't use them.
  8. Click Deploy Blueprint. The form lists something like "Create background worker … (Starter)". It doesn't show the price, but Starter is Render's smallest paid plan, $7 a month, plus about $0.25 for the 1 GB disk. Render builds your bot. In our test it was live within a minute.
  9. Check it's alive. Open your new service in Render and click Logs. Look for Your service is live. Command bots then print Logged in as followed by your bot's name, and alert bots print what they checked (for example "No new uploads or streams"). Your bot now shows as online in Discord. Try a command like /rules.

Changing settings later: edit config.yaml on GitHub (step 4). Render notices and restarts the bot by itself. To change a token or webhook, open the service in Render and click Environment.

Common problems

"Improper token has been passed" in the logs

The token is wrong or was reset. Get a new one (Reset Token in the Discord Developer Portal), then paste it in Render under Environment and save.

The bot is online but ignores commands or doesn't see messages

Switch on Server Members Intent and Message Content Intent on the Bot page, and make sure you invited it with applications.commands ticked. Slash commands can take a minute to appear. Check that GUILD_ID is your server's ID.

Render says it can't find render.yaml or a Dockerfile

You probably uploaded the folder instead of what's inside it. In GitHub, your files should be at the top level. Delete the repository and upload again, selecting the files inside the folder.

Render asks for a card, or says workers aren't free

That's expected. Background workers (always-on bots) need Render's smallest paid plan, about $7 a month.

Alerts don't arrive

Check the webhook URL is pasted in full (it starts with https://discord.com/api/webhooks/) and that the webhook still exists in the channel's settings. Alert bots check on a timer (for example every 6 hours for Free Games Radar), so the first post can take a while. The first run may only record what already exists, so you don't get flooded with old posts.

The bot posts old alerts again after a restart

Keep the 1 GB disk that render.yaml adds. It's where the bot remembers what it already posted.

Files included in every bot

Dockerfile (runs anywhere Docker runs), render.yaml (Render Blueprint: a worker on the smallest paid plan with a 1 GB disk at /data, or a free web service for the two web tools), railway.json (Railway: builds the Dockerfile and restarts on failure), and a Procfile (for hosts that read one, for example worker: python bot.py). For Railway, create a project from your GitHub repo, add the same settings under Variables, and add a volume mounted at /data so the bot remembers what it posted.
